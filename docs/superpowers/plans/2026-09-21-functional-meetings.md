# Functional Meetings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Product, Design and Engineering meetings to the Jam Cycle Map as three
independently toggleable audience groups, make every chip state its own audience so
stacked chips are readable, and allow mid-week placement.

**Architecture:** `jam-framework.json` is the data; `template.html` renders it; `build.sh`
inlines both into `index.html`. All seven audience groups become data (`meta.groups`)
that drives the toggles, the chip labels and the legend, replacing hardcoded lists in the
template. Milestone `at` widens from integer week boundaries to half-week steps. `verify.js`
grows from a smoke test into an assertion harness that guards the data invariants.

**Tech Stack:** Vanilla HTML/CSS/JS in a single template, JSON data, `python3` build script,
`node` for verification. No package.json, no dependencies, no test framework — `verify.js`
run under plain `node` is the test suite, and the browser is the check for render behavior.

---

## Spec

`docs/superpowers/specs/2026-09-21-functional-meetings-design.md`

## Testing approach

There is no test framework in this repo and adding one is not justified for a single
static page. Two layers instead:

1. **`node verify.js`** — assertion harness over `jam-framework.json` and the built
   `index.html`. Every data-shaped requirement in the spec gets an assertion here, and
   each task writes its assertion before the data or code that satisfies it. This is the
   red/green loop.
2. **Browser check** — render behavior (toggles removing chips, stacked chips reading
   correctly, mid-week ticks) is verified by loading the page and reading it back. Task 11
   does this with explicit expected observations.

`verify.js` exits non-zero on any failure, so it works as a pre-commit gate.

## Deviation from the spec, recorded

The spec describes each `meta.groups` entry as carrying `color` and `shape`. The
implementation keeps only `id`, `name`, `short` and `default` in the data, and leaves dot
colour and shape in the CSS where the rest of the page's appearance already lives.
Carrying colour in the data and then not using it to generate CSS would leave two sources
of truth for the same thing. The groups table in the spec still describes the intended
appearance; the CSS implements it.

```js
// Checks for the Jam Cycle Map. Data invariants over jam-framework.json, then
// build integrity of index.html. Exits non-zero if anything fails.
const fs = require('fs');

let failures = 0;
function check(name, fn) {
  let msg;
  try { msg = fn(); } catch (e) { msg = e.message; }
  if (msg) { console.error('FAIL  ' + name + ': ' + msg); failures++; }
  else { console.log('ok    ' + name); }
}

const D = JSON.parse(fs.readFileSync('jam-framework.json', 'utf8'));
const W = D.meta.cycleWeeks;

/* ---------- data invariants ---------- */

check('milestone ids are unique', () => {
  const ids = D.milestones.map(m => m.id);
  const dupes = [...new Set(ids.filter((id, i) => ids.indexOf(id) !== i))];
  return dupes.length ? 'duplicate ids: ' + dupes.join(', ') : null;
});

check('every milestone at is a half-week step inside the cycle', () => {
  const bad = D.milestones.filter(m =>
    m.at !== null && !(typeof m.at === 'number' && m.at >= 0 && m.at <= W && m.at * 2 === Math.round(m.at * 2)));
  return bad.length ? 'bad at: ' + bad.map(m => m.id + '=' + m.at).join(', ') : null;
});

/* ---------- build integrity ---------- */

function embedded() {
  const h = fs.readFileSync('index.html', 'utf8');
  const unesc = s => s.replace(/<\\\//g, '</');
  const get = id => {
    const m = h.match(new RegExp('<script id="' + id + '" type="application/json">([\\s\\S]*?)</script>'));
    return m ? JSON.parse(unesc(m[1])) : null;
  };
  return { h, data: get('data'), tpl: get('tpl') };
}

check('index.html embeds the current data and template', () => {
  const { data, tpl } = embedded();
  if (!data) return 'no embedded data block';
  if (JSON.stringify(data) !== JSON.stringify(D)) return 'embedded data differs from jam-framework.json — run ./build.sh';
  if (tpl !== fs.readFileSync('template.html', 'utf8')) return 'embedded template differs from template.html — run ./build.sh';
  return null;
});

check('the page script parses', () => {
  const { h } = embedded();
  const tplEnd = h.indexOf('</script>', h.indexOf('<script id="tpl"')) + 9;
  const js = h.slice(h.indexOf('<script>', tplEnd) + 8, h.lastIndexOf('</script>'));
  new Function(js);
  return null;
});

console.log(failures
  ? '\n' + failures + ' check(s) failed'
  : '\nall checks passed | ' + D.meta.version);
process.exit(failures ? 1 : 0);
```
